이미 Beta에 참여 중이신가요? 키트와 함께 받은 접속 정보로 Compare 열기.

결과물

하나의 결정. 검토 순서. 모든 결과에 evidence.

모든 비교는 빈칸 없이 명시된 결정과 검토할 차이를 돌려줍니다. 각 차이에는 시간 구간과, 기록된 evidence가 그것을 얼마나 뒷받침하는지가 함께 표시됩니다.

Decision

명시된 결과

REVIEW_REQUIRED, NO_MATERIAL_STRUCTURAL_CHANGE, INCONCLUSIVE_DIFFERENCE, INSUFFICIENT_COVERAGE 중 하나.

Presence

한 실행에만 있는 stream

Reference나 Target 중 한쪽에만 존재하는 stream.

Timing

메시지 간격 변화

Target에서 길어지거나 짧아진 기록 간격. 일시적·지속적 구분과 양쪽 값 포함.

Activity

활동 손실과 회복

한 실행에서 stream이 조용해진 구간과, 다시 돌아왔는지·언제 돌아왔는지.

Timestamps

표현 방식 변화

timestamp 정밀도 변화는 별도로 보고되며 느려진 것으로 계산되지 않습니다.

Quality

Evidence 품질과 coverage

각 결과는 comparable, limited, inconclusive로 표시되고, coverage 한계는 숨기지 않고 나열됩니다.

Your streams

각 key 옆의 내 카테고리

사용자가 지정한 카테고리를 중립 stream key 옆에 표시하고, 서로 다르게 분류된 stream이 한 key로 묶이면 알려줍니다.

Output

보관할 수 있는 리포트

HTML·Markdown 리포트, comparison_report.json(schema 0.5.0), 요약, 카테고리 표.

결과는 심각도 점수가 아니라 고정·문서화된 검토 순서를 따릅니다. VeluneOS Compare는 근본 원인, 결함, 안전성, 회귀 여부, 릴리스 가능 여부를 판단하지 않습니다. 알려진 한계: 타이밍은 기록된 로그 시간 기준이라 서로 다른 시계 사이의 지연은 평가하지 않습니다. stream은 topic 이름이 같거나 사용자가 짝을 확인한 경우에만 두 실행 사이에서 비교됩니다. 같은 타입의 센서를 하나 빼고 다른 하나를 추가한 경우는 아직 비교용으로 준비할 수 없습니다. 전체 샘플 리포트 보기.

비교 실행 방법

로컬에서 준비하고, 파생 파일 하나만 업로드.

입력: MCAP 기록 두 개, Reference 실행과 Target 실행. Reference는 사용자가 고른 기준일 뿐 정상이라는 뜻이 아닙니다. Beta 참여 팀은 Velune Adapter Beta Kit(Python 3.12 또는 3.13)를 받습니다.

  1. Beta Kit 설치 내 컴퓨터

    Velune Adapter 0.2.0과 velune 명령. 키트 다운로드 · SHA256

  2. Stream 찾기 내 컴퓨터

    두 MCAP 파일을 로컬에서 읽고 모든 stream과 등장 위치를 나열합니다.

    velune mapping init reference.mcap target.mcap --output mapping.json

  3. Stream에 이름 붙이기

    mapping.json에서 리포트에서 알아볼 stream에 canonical_subsystem_id와 canonical_category_id를 지정합니다(예: PERCEPTION / PERCEPTION_LIDAR, 최소 하나). 지정 여부와 관계없이 모든 stream이 비교되며, 지정하지 않은 stream은 중립 key로 표시됩니다.

  4. Stream 짝 확인 내 컴퓨터

    두 실행의 stream은 같은 topic 이름으로 짝지어집니다. 한쪽에만 있는 topic은 다른 실행의 같은 타입 topic과 짝지어질 수 있는데, 이름만 바뀐 topic이면 맞지만 다른 센서라면 틀립니다. 이런 짝은 모두 correspondence_review에 나열되며, 하나하나 확인하기 전까지 prepare는 진행되지 않습니다. 보통은 목록이 비어 있습니다.

  5. 준비하고 확인 내 컴퓨터

    comparison.velune과, 그 안의 모든 항목을 나열한 comparison.preview.json을 만듭니다. 업로드 전에 preview를 확인하세요.

    velune prepare reference.mcap target.mcap \
  --mapping-profile mapping.json --output comparison.velune

  6. 업로드 VeluneOS Compare

    Beta 접속 정보로 compare.veluneos.ai에 로그인해 comparison.velune을 올리세요. 리포트는 몇 초 안에 돌아오고 다운로드할 수 있습니다.

  7. 검증하고 결정 엔지니어

    검토 순서부터 보고, 카테고리 표를 확인한 뒤, 보고된 구간을 기존 도구에서 여세요. 엔지니어링 결정은 엔지니어의 몫입니다.

데이터 경계

업로드되는 것과 남는 것.

comparison.velune 안에 있는 것

  • 중립적인 stream·schema key — 원래 topic·schema 이름은 포함되지 않음
  • 각 실행 시작 기준 상대 시간의 초 단위 메시지 수와 간격 통계
  • 파일 크기, 길이 같은 실행 단위 메타데이터
  • 사용자가 지정한 카테고리
  • 각 stream이 두 실행 사이에서 어떻게 짝지어졌는지(stream key와 근거만)
  • 모든 파일의 SHA-256 해시가 담긴 manifest

절대 포함되지 않는 것

  • 원본 MCAP, rosbag2 파일
  • 메시지 payload: 이미지, point cloud, GPS 위치
  • 원래 파일·topic·schema 이름, 절대 timestamp
  • 인증 정보

서비스는 업로드마다 임시 디렉터리에서 처리하고 리포트를 돌려준 뒤 삭제합니다. 리포트는 서버에 저장되지 않습니다. 접속 로그에는 요청 시각과 상태만 기록되며 파일 내용은 기록되지 않습니다. 준비된 파일을 완전한 익명 데이터라고 설명하지 않으며, Beta 기간에는 전송 경계를 각 팀과 함께 검토합니다.

이용 방식

같은 Compare. 데이터 사용 방식만 선택합니다.

두 방식 모두 같은 엔진, 같은 리포트입니다. 어느 쪽이든 원본 MCAP은 업로드되지 않습니다.

Contribution Access · 무료

승인된 파생 데이터가 여러 고객의 승인된 데이터를 이용한 집계·비교 분석을 포함해 VeluneOS 제품과 서비스의 개발, 평가, 개선에 사용될 수 있습니다.

Private Access · 팀별 견적

데이터는 요청한 서비스를 제공하고 운영하는 데에만 사용되며, VeluneOS 제품이나 서비스 개선에 재사용되지 않습니다.

요청서에서 방식을 고르는 것은 동의가 아닙니다. 데이터 사용 조건은 첫 업로드 전에 서면으로 확정합니다. Beta는 서비스 주도로 운영됩니다. VeluneOS 운영자가 입력과 작업 상태를 확인하고 리포트 품질을 함께 검토합니다. 셀프 가입이나 온라인 결제는 없습니다.
