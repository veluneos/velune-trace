VeluneOS Compare · Private Beta

Compare two runs. See what changed.

Pick a Reference run and a Target run — before and after a change, two software versions, two robots. Velune Adapter prepares both on your machine; Compare reports the structural differences and where to look.

What you get

One decision. A review order. Evidence for every finding.

Every comparison returns a stated decision — never a blank — and the differences to review, each with its time window and how well the recorded evidence supports it.

Decision

Stated outcome

REVIEW_REQUIRED, NO_MATERIAL_STRUCTURAL_CHANGE, INCONCLUSIVE_DIFFERENCE or INSUFFICIENT_COVERAGE.

Presence

Streams in one run only

Streams that exist in the Reference run or the Target run but not both.

Timing

Message interval changes

Recorded intervals longer or shorter in Target, temporary or persistent, with values from both runs.

Activity

Activity loss and recovery

Where a stream goes quiet in one run, and whether and when it comes back.

Timestamps

Representation changes

A change in timestamp precision is reported on its own and not counted as a slowdown.

Quality

Evidence quality and coverage

Each finding is comparable, limited or inconclusive; coverage limits are listed, not hidden.

Your streams

Your categories beside each key

The categories you assigned, shown next to the neutral stream keys — with a notice if a key pairs differently classified streams.

Output

Report you can keep

HTML and Markdown report, comparison_report.json (schema 0.5.0), summary and category table.

Findings follow a fixed, documented review order — not a severity score. VeluneOS Compare does not decide root cause, fault, safety, regression or release readiness. Known limits: timing is read from recorded log time, so latency between clocks is not assessed. A stream is compared across runs only when it keeps its topic name or you confirm the pairing; a removed and an added sensor of the same type cannot be prepared for comparison yet. How a comparison runs

Prepare locally. Upload one derived file.

Input: two MCAP recordings, a Reference run and a Target run. Reference is the baseline you choose — not a claim that it is correct. Beta participants receive the Velune Adapter Beta Kit (Python 3.12 or 3.13).

  1. Install the Beta Kit your machine

    Velune Adapter 0.2.0 and the velune command. Download kit · SHA256

  2. Discover streams your machine

    Reads both MCAP files locally and lists every stream and where it appears.

    velune mapping init reference.mcap target.mcap --output mapping.json

  3. Name your streams

    In mapping.json, set canonical_subsystem_id and canonical_category_id (for example PERCEPTION / PERCEPTION_LIDAR) for the streams you want to recognise in the report — at least one. Every stream is compared either way; unassigned streams appear by neutral key.

  4. Confirm stream pairings your machine

    Streams are paired across runs by identical topic name. If a topic exists in only one run, the Adapter may pair it with a same-type topic in the other run — right for a renamed topic, wrong for a different sensor. Every such pairing is listed under correspondence_review; prepare will not continue until you confirm each one. Usually the list is empty.

  5. Prepare and review your machine

    Writes comparison.velune and comparison.preview.json, which lists every entry in the file. Read the preview before uploading.

    velune prepare reference.mcap target.mcap \
  --mapping-profile mapping.json --output comparison.velune

  6. Upload VeluneOS Compare

    Sign in with your Beta credentials at compare.veluneos.ai and upload comparison.velune. The report comes back in seconds and can be downloaded.

  7. Verify and decide your engineers

    Start with the review order, check the category table, then open the reported windows in your own tools. The engineering decision is yours.

Data boundary

What is uploaded, and what stays with you.

Inside comparison.velune

  • Neutral stream and schema keys — never the original topic or schema names
  • Per-second message counts and interval statistics, in time relative to the start of each run
  • Run-level metadata such as file size and duration
  • The categories you assigned
  • How each stream was paired across runs (stream key and basis only)
  • A manifest with SHA-256 hashes of every file

Never included

  • Raw MCAP or rosbag2 files
  • Message payloads: images, point clouds, GPS positions
  • Original file, topic and schema names; absolute timestamps
  • Credentials

The service processes each upload in a temporary directory that is deleted when the report is returned; reports are not stored on the server. Access logs record request time and status, not file contents. We do not describe the prepared file as fully anonymous; during the Beta, transfer boundaries are reviewed with each team.

Access

Same Compare. You choose how your data may be used.

Both options use the same engine and produce the same report. Raw MCAP is never uploaded under either.

Contribution Access · no fee

Approved derived data may be used to develop, evaluate and improve VeluneOS products and services, including aggregate or comparative analysis across customers' approved data.

Private Access · quoted per team

Your data is used only to provide and operate the service you requested. It is not reused to improve VeluneOS products or services.

Choosing an option in a request is not consent. Data-use terms are confirmed in writing before your first upload. The Beta is service-led: a VeluneOS operator checks inputs and job status and reviews report quality with you. There is no self-service signup or online checkout.
